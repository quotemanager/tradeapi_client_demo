# 快速接入

示例只消费已运行的本机交易 API，不启动官方客户端、不输入密码或验证码。先获取与客户端兼容的完整运行包，按随包说明安装自己的账户使用文件。

## 运行顺序

通达信：配置客户端路径 → 运行包启动 API 和客户端 → 在该窗口手动登录 → 查状态 → 查询或交易。

同花顺：配置客户端路径 → 启动 API；也可先登录客户端 → 查状态 → 查询或预览 → 预览就绪后提交。

`/health` 仅表明服务存活，不代表券商已登录。切换账户后再次检查登录状态；已建立的同花顺预览不能跨账户复用。

## 连接配置

示例只允许 `http://127.0.0.1:<端口>`，不通过网络代理，不自动跟随重定向。默认超时90秒；不自动重试。所有命令示例从仓库根目录执行。

| 环境变量 | 用途 |
| --- | --- |
| `TRADEAPI_TDX_URL` | 通达信本机 API 地址，默认18769 |
| `TRADEAPI_TDX_TOKEN` | 通达信运行包 `config/service-token.txt` 的内容，去掉首尾空白 |
| `TRADEAPI_THS_URL` | 同花顺本机 API 地址，默认18768 |
| `TRADEAPI_THS_TOKEN` | 同花顺运行包 `runtime/client.json` 中的 `token` |
| `TRADEAPI_TDX_HOME` | 仅 SDK／DLL 模式使用，通达信运行包根目录 |
| `TRADEAPI_THS_HOME` | 仅 SDK／DLL 模式使用，同花顺运行包根目录 |

HTTP例子读取环境变量；Python SDK使用 `HOME` 指向运行包中的连接配置。DLL模式需要同时设置对应的URL、TOKEN和HOME。不要设置成官方客户端目录，也不要把这些环境变量的真实值提交Git。

## 命令约定

所有语言使用 `PRODUCT COMMAND VALUE`，产品为 `tdx` 或 `ths`。默认命令是 `query funds`。

| 命令 | 通达信 | 同花顺 | VALUE |
| --- | :---: | :---: | --- |
| `health` / `status` | ✓ | ✓ | 无 |
| `query` | ✓ | ✓ | 统一查询名，省略为funds |
| `order` / `cancel` | ✓ | — | 用户创建的JSON文件 |
| `preview-order` / `preview-cancel` | — | ✓ | 用户创建的JSON文件 |
| `poll-order` / `poll-cancel` | — | ✓ | 已取得的preview_id |
| `submit-order` / `submit-cancel` | — | ✓ | 已就绪的preview_id |
| `result` | ✓ | ✓ | 已保存的request_id或action_id |

真实提交默认仅打印参数，增加 `--execute` 才发送。预览可能触发业务检查，但不会发送最终委托；不会自动提交后续步骤。JSON文件必须为UTF-8对象，大小不超过64KiB。

## 本地交易参数

复制所需 `config/*.example.json` 为 `config/*.local.json`。本地文件已被Git忽略；仍需自行检查不要包含密码或令牌。

价格是字符串，例如 `"17.72"`；证券代码和合同号也用字符串，避免前导零消失。数量是整数。通达信每笔新动作的 `request_id` 必须唯一，可在PowerShell中用 `[guid]::NewGuid().ToString('N')` 生成，发送前保存。

不要为了重试生成新编号；超时或未知结果先核对客户端。同花顺的预览就绪、过期时间和实际参数须在提交前检查，不能沿用旧账户或旧预览。

## 常见问题

| 问题 | 检查事项 |
| --- | --- |
| 连接被拒绝 | API是否运行；端口是否与运行包配置一致 |
| HTTP401 | 本机TOKEN是否正确，是否重新生成过；不要贴真实TOKEN |
| HTTP403或账户不可用 | 当前登录账户是否正确；联系管理员核对所用运行包及账户权限 |
| DLL无法加载 | HOME是否指向完整运行包；DLL位数是否与调用进程一致 |
| 同花顺预览尚未就绪 | 过约0.5秒后用同一个ID查询一次预览；不要直接提交 |
| 合同号为空或pending | 保留响应与ID，核对客户端委托及成交，不自动重发 |
| 查询数据看起来滞后 | 同花顺可能读取客户端快照；读取时间不等于券商更新时间 |

接口返回字段不同，示例保留原始JSON，不把两套明细强行合并。多个调用应串行执行，尤其不要同时提交或切换账户。
